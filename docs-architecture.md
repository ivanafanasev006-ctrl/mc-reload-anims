# Kinetrix (бывш. MC Reload Animations): архитектура и решения

Текущая версия: **1.0.3-beta**.

**Цель:** анимации игрока в духе Mo' Bends для Forge 1.20.1. Мод работает самостоятельно и плавно смешивается с Better Combat, Iron's Spells 'n Spellbooks и Emotecraft.

**Репозиторий:** `ivanafanasev006-ctrl/mc-reload-anims`. Каждый пуш в `main` собирается на GitHub Actions. Результат публикуется как pre-release и в ветку `dist`, где лежат jar и `build.log`. Artifacts не используем: квота на аккаунте закончилась.

## Визуальный автотест (`selftest.yml`)
- В CI запускается настоящий клиент Forge 1.20.1 (`runClient -Pselftest`) под Xvfb с программным OpenGL (Mesa llvmpipe, 4–10 FPS).
- Тестовый режим `dev.mcreload.anim.client.selftest` включается только свойством `-Dmcreload.selftest=true`. Он:
  - сам создаёт мир, строит трек, бассейн и лестницу;
  - водит игрока через `ScriptedInput`: нажатия клавиш в Xvfb не работают;
  - снимает кадры из цикла отрисовки, мир плюс панели «сбоку / спереди / сверху» (вид сверху с v0.6, чтобы ловить пролезание конечностей сквозь тело).
- Около 30 сценариев. Результат пушится в ветку `selftest`.
- Сценарии стартуют только после того, как сервер достроил трек (`worldReady`): на медленной машине первые сценарии однажды прошли в точке спавна.
- **Ограничения CI.** Звуковой карты нет, поэтому реакции на звук (взрыв, блок щитом, тотем) тест вызывает напрямую. Элитры запускаются пакетом START_FALL_FLYING, сон через `startSleeping`, безделье через `MotionState.forceIdle`.

## Тест совместимости (`compat.yml`)
- Настоящий (production) клиент Forge 1.20.1-47.4.20 через лаунчер **portablemc** под Xvfb: собранный reobf-jar Kinetrix + моды с Modrinth (по id версии): playerAnimator, Skin Layers 3D 1.11.1, ETF 6.2.9 + EMF 2.4.1, Cloth Config, Better Combat 1.9.0 + Better Combat Particle, Architectury + Vintage Animations 1.3.0, Embeddium 0.3.31, Iron's Spells 3.4.0.x с GeckoLib, Curios и Caelus (новейшие сборки для 1.20.1, ищутся при запуске). Ресурспаки: Fresh Moves v3.1 и тестовый скин с полным внешним слоем (`ci/compat/testskin.png`, подменяет все 9 дефолтных скинов).
- В dev-окружении (`fg.deobf`) Skin Layers 3D не запускается: вложенная библиотека TRansition остаётся с SRG-именами. Поэтому тест совместимости — только production.
- `options.txt`: паки НЕ класть в `incompatibleResourcePacks` — ванилла тогда снимает их с выбора («now compatible» без добавления).
- Подмножество сценариев: `-Dmcreload.selftest.only=<regex>`. Сценарий `65_friend` — второй игрок (FakePlayer, сервер двигает его и шлёт sync-пакеты), `99_emf_player` — отдаёт модель игрока EMF (F3+T) и проверяет, что ничего не ломается.
- FakePlayer не тикает: предмет в руке рассылать вручную (`ClientboundSetEquipmentPacket`).

## Решения
- **Платформа:** Forge 1.20.1 (47.x), Java 17, ForgeGradle 6, Gradle 8.8.
- **Движок:** playerAnimator (`dev.kosmx.player-anim:player-animation-lib-forge:1.0.2-rc1+1.20`). Это единственная жёсткая зависимость.
- Iron's Spells читается через рефлексию. Better Combat определяет гармонизатор.
- Референс: Mo' Bends (MIT, github.com/mobends/MoBends) и Fresh Animations: Player (только по видео, идеи).

- **v0.8.0 (21.10.2026) — главная находка:** на Forge playerAnimator сгибает конечности ТОЛЬКО при установленном bendy-lib (`IBendHelper.INSTANCE` = DummyBendable без него). Ни у пользователя, ни в CI его не было, поэтому все bend-ы (колени, локти, наклон корпуса) с v0.1 по v0.7 не отрисовывались — отсюда «6 частей, которые дрыгаются». Решение — свои суставы:
  - `client/joint/*` + mixins (`dev.mcreload.anim.mixin`, MixinGradle 0.7, `mcreload.mixins.json`) + access transformer (ModelPart non-final, Polygon/Vertex public).
  - `Joint`: грани кубов режутся по линии сустава (`Clip`, Sutherland–Hodgman, UV интерполируются) один раз и хранятся в самом `Joint` (массивы вершин). С 1.0.2 детали модели не меняются вовсе: пока сустав согнут, `AgeableListModelMixin` (HEAD `renderToBuffer`, cancel) сам рисует модель — разрезанные детали двумя половинами (`Joint.draw`: неподвижная, затем шарнир и подвижная, дети детали — обычным `render`), голова и руки при согнутом поясе через `applyNeck`/`applyUpperBody`, остальное — `ModelPart.render`. Прямые конечности рисует ваниль. Шарнир на внешнем ребре сгиба (колено — передний край, локоть — задний, пояс — задний), ось как в playerAnimator: (cos(-axis),0,sin(-axis)).
  - `JointRig` на PlayerModel (рука+рукав, нога+штанина, тело+куртка) и на моделях брони игрока (из `PlayerRenderer.<init>`). Bend читается из `AnimationApplier.getBend(...)` в `setupAnim` RETURN → гнутся анимации любых модов на playerAnimator. Броня получает через `copyPropertiesTo`.
  - Пояс: `AgeableListModel.renderToBuffer` HEAD — верхние части (руки, рукава) рисуются с B·H·B⁻¹ (B — трансформ тела), голова только переносится за шеей, не поворачиваясь. Предмет в руке: `PlayerModel.translateToHand` HEAD (пояс) / RETURN (локоть + наклон оружия в кулаке `itemTilt`). Первое лицо — без сгибов (`renderHand`).
  - Если bendy-lib установлен — наша система выключается.
  - Анимации переписаны по Mo' Bends (MIT, исходники в github.com/mobends/MoBends): стойка (расслабленная), ходьба, спринт, присед (отменяем ванильный наклон 0.5 и смещения частей), `BladeModule` — удары мечом/топором (рука `Ry·Rz` из Mo'Bends → Euler через `AngleMath.toModelEuler`, поворот корпуса `twistShoulders`), стойка только 3 с после боя и стоя. Торможение — 0.45 с «скейт». Меч в землю — на колено, двумя руками, руки горизонтально в мире + roll π. Кувырок после элитр убран.
  - Перевод Mo'Bends: градусы→радианы; forearm X → bend (локоть отрицательный), foreleg X → bend (колено положительный), body X → torso bend, body Y → twist (тот же знак), globalOffset (px, + вверх) → body.py в блоках (×0.9375/16).

  - **Наклон оружия в кулаке** (`itemTilt`): знак перевёрнут (`rotationX(+tilt)`), иначе клинок уходил в тело в боевой стойке и при ударах.
  - **Лук** — как в ванилле: руки целятся по камере, рука с луком прямая, тянущий локоть 0.20 + 0.75·натяжение, без наклона пояса; стойка ногами только стоя.
  - **Щит** — `crouch(0.28)` + наклон, ноги продолжают шагать (стойка ногами только стоя).
  - **Еда** — рука ко рту по IK (x −1.25 + pitch·0.3, локоть 1.20), без лишнего изгиба.
  - **Торможение** — «скейт» 0.55 с: корпус боком 70°, ноги ±28°, колени 50°, присед 3 px, руки в стороны.
  - **Вода:** «дельфин» только при входе с суши (`fromLand` = >20 тиков без воды) с высоты ≥1.4 блока (`airStartY`); в воздухе над водой корпус головой вниз (`body.rx` −(1.35 + 1.30·крутизна); −π/2 = лёжа, −π = вниз головой); при входе −2.65 → −1.50 рад (выравнивание под водой). Плавание без спринта — вертикально, по референсу пользователя (treading water): плечи над водой (`surfaceDepth`), руки в стороны и вперёд, гребут «восьмёркой» (`sc = t·4.2`), ноги «взбивалкой» (бедро −0.30 ± 0.18, колено 0.75 ± 0.35, ноги в противофазе). **Chill-падение:** назад (S) с ≥4 блоков в воду → на спину, руки за голову, колено вверх. После телепорта 2 тика игнорируем старое состояние воды (`teleportTick`).
  - **Меч в землю:** вместо roll π руки (Эйлер-roll на π прыгал между двумя эквивалентными решениями, пружины интерполировали через «обратную сторону») клинок переворачивается в кулаке через `itemTilt` (0.95 → π): руки к горизонтали в мире (`−1.50 − lean − 0.30` в системе торса), клинок входит в землю перед передним коленом. **Падение с мечом** (`AirModule.bladeFall`): обе руки на рукояти над головой, клинок вверх (`itemTilt` 0.95), колени подтянуты — переходит в удар при посадке. При телепорте водные веса сбрасываются сразу.
  - **Копание руками** (`FIST_BLOCK`: тянется → врезается → выгребает к себе, руки по очереди) и **установка блока** (`PLACE`, по `keyUse` у себя / BlockItem у других): рука вдавливает блок; обе целятся по pitch, наклон идёт в пояс и колени (`crouch`), а не всем телом.
  - **Верховая езда** (`RideModule.mount`): ноги вдоль боков, колени 1.0, корпус «постит» в такт аллюру, на галопе наклон, руки на поводьях.
  - **Взрыв / тотем / эмоции** переделаны под суставы (локти, колени, пояс).

## Соглашения о знаках
- Изгиб (bend): `Signs.knee = +1`, `elbow = −1`, `torso = +1`.
- `body` rotX отрицательный = наклон вперёд, rotZ отрицательный = крен вправо, ry положительный = правое плечо вперёд (компенсация: голова и руки получают тот же ry). Позиция `body` в блоках, точка опоры +0.7, +Z = назад.
- Рука: x −1.57 = вперёд, y+ поворачивает вытянутую руку к модели −X (вправо от игрока). Для правой руки это «наружу», для левой «внутрь». z+ = наружу для правой руки.
- Поклон/наклон корпусом: `body.rx` вперёд уводит ноги назад, поэтому ногам нужен такой же поворот вперёд (отрицательный x), чтобы стопы остались под телом.
- Клинок перпендикулярен руке: рука вниз → клинок вперёд и чуть вверх (≈0.17 рад). `itemTilt` (поворот вокруг оси X кулака) + = клинок к продолжению руки; π = клинок в обратную сторону без переворота руки. `roll` (поворот вокруг оси руки): +π/2 клинок наружу, −π/2 внутрь, π — в обратную сторону (рука вперёд + roll π = клинок вниз). Для левой руки знак roll зеркалится.
- Twist + = правое плечо назад.
